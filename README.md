# Moly's Log

Pet medical history organizer — CETYS Cloud Computing project (Luis Vargas, Jorge Octavio).
This repository holds the **Second Draft** infrastructure (Terraform) and boilerplate, plus the Cloud Security Lab work.

## Architecture

| Component | Azure resource | Notes |
|---|---|---|
| Frontend (React + Vite) | Static Web Apps (Free) | Calls the API directly over HTTPS with CORS |
| REST API (Node 22) | Azure Functions, Flex Consumption (FC1) | System-assigned managed identity |
| Database | PostgreSQL Flexible Server (B1ms, v16) | Admin password generated by Terraform, stored only in Key Vault |
| Files | Blob Storage (`pet-documents`) | Account keys disabled; identity-only access |
| Secrets | Key Vault (Azure RBAC) | App: *Secrets User*; admin: *Secrets Officer* |
| Monitoring | Application Insights + Log Analytics | 0.5 GB/day cap |
| CI/CD auth | User-assigned identity `id-github-actions` | OIDC federated credential, `main` only |

All resources deploy to **centralus**: the subscription's allowed-regions policy (westus, brazilsouth, northcentralus, mexicocentral, centralus) overlaps with Static Web Apps regions only there.

The Free SWA plan cannot link a "bring your own" Function App (Standard plan, ~USD 9/month), so the frontend calls the Function App URL with CORS restricted to the SWA hostname.

## Layout

```
infra/      Terraform (all Azure resources)
api/        Azure Functions: GET /api/health (Key Vault ref, PostgreSQL, Blob checks)
frontend/   React app showing API health
scripts/    deploy.sh, verify.sh, scan-secrets.sh, rotate-db-password.sh
.github/    ci.yml (gitleaks, terraform validate, tests, build) and deploy.yml (OIDC)
docs/       STATUS.md
```

## Deploy

```bash
az login
az provider register -n Microsoft.DBforPostgreSQL   # once per subscription
cd infra
cp terraform.tfvars.example terraform.tfvars   # set subscription_id and github_repository
terraform init
terraform plan -out tfplan
terraform apply tfplan
cd .. && ./scripts/deploy.sh && ./scripts/verify.sh
```

Requires Terraform ≥ 1.11 (write-only attributes keep the DB password out of state), Azure CLI, Node 22+.

## GitHub Actions (OIDC)

After `terraform apply`, create the repository secrets `AZURE_CLIENT_ID` (output `github_oidc_client_id`), `AZURE_TENANT_ID` and `AZURE_SUBSCRIPTION_ID`. None is a password. The federated credential trusts only `repo:<owner>/<repo>:ref:refs/heads/main`; running `deploy.yml` from `test-oidc` must fail at login.

## Secrets policy

No credentials in code or history. `.env`, `*.tfstate`, `*.tfvars`, `local.settings.json` and scan reports are gitignored; `.env.example` lists variable names only. Run `./scripts/scan-secrets.sh` for a full-history Gitleaks scan.
