# Moly's Log

Pet medical history organizer — CETYS Cloud Computing project (Luis Vargas, Jorge Octavio).
This repository holds the **Second Draft** infrastructure (Terraform) and boilerplate, plus the Cloud Security Lab work.

## Architecture

| Component | Azure resource | Notes |
|---|---|---|
| Frontend (React + Vite) | Static Web Apps (Free) — intended; Storage static website — deployed fallback | Same build for both; calls the API over HTTPS with CORS |
| REST API (Node 22) | Azure Functions, Flex Consumption (FC1) | System-assigned managed identity |
| Database | PostgreSQL Flexible Server (B1ms, v16) | Admin password generated by Terraform, stored only in Key Vault |
| Files | Blob Storage (`pet-documents`) | Account keys disabled; identity-only access |
| Secrets | Key Vault (Azure RBAC) | App: *Secrets User*; admin: *Secrets Officer* |
| Monitoring | Application Insights + Log Analytics | 0.5 GB/day cap |
| CI/CD auth | User-assigned identity `id-github-actions` | OIDC federated credential, `main` only |

## Frontend hosting: SWA retained, Blob fallback deployed (deviation)

The course requires **Azure Static Web Apps**, and `infra/` keeps that configuration (`frontend_hosting = "swa"`, the default).
It **cannot be deployed on the team's active subscription**: Azure for Students enforces the policy
*Allowed resource deployment regions* (effect `deny`) with `westus, northcentralus, mexicocentral, brazilsouth, canadacentral`,
while SWA is only offered in `westus2, centralus, eastus2, westeurope, eastasia`. The second team subscription (which allowed `centralus`) is disabled (no credit left).
We did not request or create a policy exemption.

Therefore the deployment uses `frontend_hosting = "blob"`: the same React build served from the storage account's static website (`$web`, `westus`).
**This is a documented deviation from the professor's requirement, not SWA compliance.** Differences: no SWA-managed headers/routing config
(`staticwebapp.config.json` is ignored; SPA fallback uses the static website 404 document, which returns HTTP 404 with `index.html`), no SWA preview environments.
Security is unchanged: storage account keys stay disabled, uploads use Entra ID (`--auth-mode login`), only `$web` is publicly readable, and Function CORS allows only the frontend origin.
Switching back is one variable: `frontend_hosting = "swa"` on a subscription that allows a SWA region.

All other resources deploy to `location` (`westus`), except PostgreSQL: `postgres_location = "northcentralus"` because Azure returned `SkuNotAvailable` for B1ms in westus on this subscription.

The Free SWA plan cannot link a "bring your own" Function App (Standard plan, ~USD 9/month), so in both modes the frontend calls the Function App URL directly.

## Deploy

```bash
az login
az provider register -n Microsoft.DBforPostgreSQL   # once per subscription
cd infra
cp terraform.tfvars.example terraform.tfvars   # set subscription_id, github_repository, frontend_hosting
terraform init
terraform plan -out tfplan
terraform apply tfplan
cd .. && ./scripts/deploy.sh && ./scripts/verify.sh
```

Requires Terraform ≥ 1.11 (write-only attributes keep the DB password out of state), Azure CLI, Node 22+.

## GitHub Actions (OIDC)

After `terraform apply`, create the repository secrets `AZURE_CLIENT_ID` (output `github_oidc_client_id`), `AZURE_TENANT_ID` and `AZURE_SUBSCRIPTION_ID`. None is a password. The federated credential trusts only `main`. GitHub sends the newer immutable-ID subject `repo:Luisvvargas@130583049/molys-log@1464980155:ref:refs/heads/main` (set via `github_oidc_repo_claim`); running `deploy.yml` from `test-oidc` must fail at login.

## Secrets policy

No credentials in code or history. `.env`, `*.tfstate`, `*.tfvars`, `local.settings.json` and scan reports are gitignored; `.env.example` lists variable names only. Run `./scripts/scan-secrets.sh` for a full-history Gitleaks scan.
